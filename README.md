# みらい博物館 / MIRAI MUSEUM

子どもが「遊んでいるうちに、世界のなぜ？に出会う」ことを目指すWebゲーム。

> 走って、跳んで、見つける。  
> 遊んでいるうちに、世界の「なぜ？」に出会える博物館。

## 実装済みMVPを遊ぶ

Nuxt 4 + Phaser 3 + TypeScript で、恐竜の世界を1ステージ実装しています。

```sh
npm ci
npm run dev
```

Node.js は **22.19 以上の22系、24.11以上の24系、または26以上**を使ってください。クラウド環境では npm コマンドの前に `export npm_config_cache=/workspace/.cache/npm` を実行します。

開発サーバーはポート3000で起動します。「冒険をはじめる」からすぐに遊べます。スマートフォンでは画面をタップ、PCではクリック・Space・↑で固定高のジャンプ。ⅡボタンまたはEscで一時停止できます。ページが非表示になると自動で一時停止します。

プレイ中はサイトのヘッダーを隠し、スマートフォンの縦画面ではブラウザーの表示領域いっぱいにゲームを表示します。画面の縦横比やブラウザーのバーの高さが変わっても、キャラクターを引き伸ばさず描画範囲を調整します。横持ちとPCでは縦長のゲーム画面を中央に表示します。音の切り替えと博物館への移動は一時停止画面から行えます。

約80秒のステージは、地層・化石の世界 → 白亜紀の森 → ティラノサウルスとの遭遇 → 発掘と展示の演出、という流れです。障害物にぶつかると少し戻って再挑戦。同じ障害物で3回つまずくとジャンプを手伝います。高い位置にある発見は、タイミングを合わせたジャンプで集められます。

発見は全6種類。ゴールすると博物館へ展示され、ブラウザーのlocalStorageに自動保存します。同じ発見を集めると新しい短い知識が増えます。保存は端末・ブラウザーごとで、ログインやクラウド同期はありません。途中で博物館に戻った冒険の発見は保存されません。保存が使えないブラウザーでも、そのページ内では遊べます。宇宙・深海のステージは準備中です。

ピクセルアートとWeb AudioのBGM・効果音は、この実装のために作成したものです。実行時に外部の素材・フォント・APIを取得する必要はありません。

### VS CodeのDev Containerでデバッグ

Docker Desktop（LinuxはDocker Engine）、VS Codeの **Dev Containers** 拡張、ホスト側のChromeまたはEdgeを用意してください。ホストへのNode.jsのインストールは必要ありません。

1. このリポジトリをVS Codeで開き、コマンドパレットから **Dev Containers: Reopen in Container** を実行します。
2. 初回はNode.js 24のコンテナをビルドし、`npm ci`を自動実行します。コンテナにはブラウザーテスト用のChromiumも入ります。
3. 「実行とデバッグ」で **MIRAI: Chrome** または **MIRAI: Edge** を選び、**F5**を押します。Nuxtの起動を待って、ホスト側のブラウザーが開きます。
4. `app/game/expedition.ts`の`jump()`や`update()`、`app/game/DinosaurScene.ts`、Vueコンポーネントにブレークポイントを置いて操作します。ゲームのファイルは「冒険をはじめる」を押すと読み込まれます。

コンテナのポート3000をホストの3000へ転送します。デバッグを始める前に、同じポートを使うサーバーを止めてください。Chrome/Edgeはホスト側で起動する設定なので、コンテナの画面環境を用意する必要はありません。

サーバー側の処理を調べるときは **Nuxt: server (SSR)** を選んでF5を押し、転送されたポート3000をブラウザーで開きます。ゲームロジックとクライアント側のVueはChrome/Edge、SSRはNode.jsのデバッガーを使います。

ブラウザーのデバッグを終了してもNuxtのタスクは動き続けます。止めるときは、そのターミナルでCtrl+C、または **Tasks: Terminate Task → Nuxt: dev** を実行してください。型チェックと単体テストも **Tasks: Run Task** から実行できます。

`node_modules`はチェックアウトごとのDockerボリュームへ保存し、ホストの依存関係と分けています。依存関係を更新した後はコンテナ内で`npm ci`を実行してください。Dockerfileなどを変更した場合は **Dev Containers: Rebuild Container** で反映します。ブラウザーテストはコンテナ内のターミナルで`npm run test:e2e`を実行できます。

### 検証と本番起動

```sh
npm test           # ゲーム進行・ジャンプ・救済・セーブの6テスト
npm run typecheck
npm run build
npm run preview    # 本番サーバー。既定ポート3000
npm run test:e2e   # 本番ビルド + PC/スマートフォンのブラウザーテスト
```

ブラウザーテストはChromiumを使い、実際のタップで全ステージを走って、6種類の発見、停止・再開、展示、保存、再読み込みを確認します。実行には約90秒かかります。クラウド環境の `/usr/bin/chromium` を自動検出します。他の環境では `npx playwright install chromium` で用意するか、`PLAYWRIGHT_CHROMIUM_EXECUTABLE` にブラウザーのパスを指定してください。テスト用サーバーはポート3001を使います。

### 主なファイル

- `app/app.vue`：タイトル・ステージ選択・博物館・ゴール後の発見紹介
- `app/components/GameStage.client.vue`：クライアントでのゲーム起動、停止、通知、破棄
- `app/game/DinosaurScene.ts`：Phaserの描画・入力・時代の移行演出
- `app/game/expedition.ts`：自動移動・ジャンプ・衝突・発見・救済
- `app/data/discoveries.ts`：展示する知識と再発見時のひとこと
- `app/data/sprites.ts`：オリジナルのピクセルアート
- `app/game/progress.ts`：セーブの検証と更新

以下はゲームのコンセプト・仕様です。

## 1. コンセプト

- 舞台は、あらゆる学問を扱う謎の「みらい博物館」。
- 対象年齢は **6〜9歳（小学校低学年）** を中心とする。
- キャラクターは自動で進み、基本操作は **画面をタップしてジャンプ**するだけ。
- ゲームオーバーは設けない。失敗を恐れず試せるゲームにする。
- 各ステージをクリアしながら「発見」を集め、博物館を充実させる。
- 「勉強させるゲーム」ではなく、普通に遊んでいるうちに知らないものに出会い、自然に興味が生まれることを目指す。
- 学習の基本サイクルは **発見する → 一言だけ知る → 博物館に展示される → 興味があれば詳しく見る**。
- 正解を暗記させるより、**予想する → 試す → 結果を見る → 発見する**体験を重視する。
- 現実世界で行う宿題やミッションは設けず、ゲーム内で完結させる。
- 表現はゲームとして大胆にデフォルメしてよいが、伝える知識そのものには嘘を入れない。

## 2. 基本ゲームループ

1. 博物館またはタイトルからステージに入る
2. キャラクターが自動で進む
3. タップを使ってジャンプや、その世界固有のアクションを行う
4. 障害物や仕掛けを越えながら「発見」を集める
5. 1〜2分程度でゴール
6. 「今回の発見」を1〜2個、大きく紹介する
7. 博物館へ戻る
8. 発見したものが展示に追加される
9. 発見を重ねることで、新しい世界・展示室が開いていく

短期目標は「ステージのゴール」、長期目標は「発見を集め、博物館を広げる」。

## 3. 操作

### 基本操作

- キャラクターは自動で前進する。
- 画面のどこをタップしてもジャンプする。
- ジャンプの高さは毎回同じ。
- タップの長さによるジャンプ高の変化や二段ジャンプは、初期仕様には入れない。
- PCでの入力方法は実装時に追加可能だが、ゲームデザインの基準はスマートフォンのタップ操作とする。

### 世界によるタップの変化

入力方法は「タップ」のまま保ち、世界によって起きるアクションを変えられる。

例:

- 地上: ジャンプ
- 宇宙: 噴射
- 水中: 泳ぐ
- 空: 羽ばたく

新しい操作方法を覚えなくても、新しい体験を得られることを狙う。

## 4. 失敗の扱い

- ゲームオーバーはない。
- 障害物にぶつかった場合は **少しだけ戻され、同じ場所に再挑戦**する。
- 何度失敗しても先へ進める。
- 敵を倒すことはゲームの中心にしない。
- ティラノサウルス、落雷、隕石などは「悪者」ではなく、その世界に存在する生物・現象として扱う。

## 5. 「発見」システム

### 発見できるもの

「モノ」だけではなく、人類の知識そのものをコレクション対象とする。

- 生き物
- 化石・鉱物・植物・道具などのモノ
- 人物
- 出来事
- 概念（重力、進化、ゼロ、電気など）

### ステージ上の見せ方

発見物によって表現を使い分ける。

- 普通の発見: 実物の姿を見せる
- 珍しい発見: シルエット、「？」、光などで正体を隠す
- 一部: ジャンプをうまく使わないと取れない場所に置く
- ときどき: クイズや特別な発見イベントを入れる

発見した瞬間にゲームは止めない。名前と短い演出・効果音だけを表示し、詳しい情報はゴール後や博物館で扱う。

### 配置

- 重要な発見は固定配置にする。
- 一部の小さな発見・レア発見はランダムにできる。
- 「前に見えたものを次こそ取る」という上達と、「前回はいなかった」という驚きを両立する。

### 再発見

同じものを再び見つけても無駄にはしない。再発見するたびに、少しずつ違う情報を得られる。

例:

1. 「ティラノサウルス！」
2. 「大きくて丈夫な歯を持っていた」
3. 「嗅覚が発達していたと考えられている」

一度に長い説明を読ませず、何度も出会うことで自然に詳しくなる。

### 進捗表示

星評価ではなく **発見率** を使う。

例:

> 恐竜の世界　発見 4 / 7

未発見のものは「？」やシルエットとして表示し、「まだ知らないものがある」こと自体を次に遊ぶ動機にする。

## 6. 博物館

### ハブとしての博物館

- 最初は一部の展示室だけが開いている。
- 発見を集めると新しい展示や展示室が増える。
- 展示物に触れることで、そのテーマの世界へ入る。
- ステージは「博物館の中を走る」のではなく、展示物の中の世界を冒険する。

### 学問の整理

子どもに対しては学問名を前面に出しすぎない。

表側では:

- 恐竜の世界
- 宇宙の世界
- 海・深海
- 古代文明
- 未来・ロボット

など、興味を引く「世界」として見せる。

内部データでは:

- 生物学
- 古生物学
- 地質学
- 物理学
- 天文学
- 歴史学
- 数学
- 情報科学

などの学問体系と関連付ける。

ひとつの世界から複数の学問へ自然に触れられる設計にする。

### 発見同士のつながり

初期版では、発見物を展示棚に並べるシンプルな構造にする。

将来は、例えば

> リンゴ → ニュートン → 重力 → 月 → 宇宙

のように、発見同士の関係を辿れる仕組みに発展させる。

## 7. ステージ構造

- 1ステージは **1〜2分程度**。
- 初期版は一本道。
- 将来は、ときどき分岐するルートを追加する。
- 分岐後には別の生き物や発見を配置し、「あそこに何かあったからもう一度遊びたい」を作る。
- 基本速度は普通。高難度化のために速度を上げることは中心にしない。
- 障害物を避けるだけでなく、「乗る・触る・出会う」仕掛けを多くする。
- 世界ごとの特徴を仕掛けに反映する。

## 8. 繰り返し遊ぶ理由

優先順位は **発見 > ごほうび > スコア**。

- 取り逃した発見を探す
- 同じものを再発見して知識を深める
- 新しい展示を増やす
- キャラクターや衣装などのごほうびを得る余地を持たせる
- 将来の分岐ルートで別の発見に出会う

コインやゲーム内通貨は、少なくとも初期版には入れない。

## 9. クイズと学び

- クイズはゲーム進行の中心にはせず、ときどき現れる特別な発見として扱う。
- 「不正解だから失敗」にはしない。
- 選んだ答えによって実際に何が起きるかを見せる。

例:

> 「月と地球、同じ力でジャンプしたらどうなる？」

予想した後、実際にキャラクターをジャンプさせて違いを見る。

ゲーム全体として、正解・不正解よりも **予想 → 実験 → 発見** を重視する。

## 10. キャラクター

- ゲーム開始時またはゲーム内で、自分のキャラクターを選べる構想とする。
- 子ども、ロボット、動物など複数タイプを用意できる。
- キャラクターによる性能差は基本的につけない。

### 案内ロボット

「みらい博物館」の案内役としてロボットが存在する。

役割は先生ではなく、プレイヤーと一緒に不思議がる相棒。

例:

> 「あれ？ 月ではジャンプが高くなったね。なんでだろう？」

- 普段は博物館にいる。
- ステージには常駐せず、大事な発見やイベントのときに現れる。
- 答えをすぐに教えず、「なぜ？」を残す。

## 11. 世界観と長期ストーリー

- なぜ展示物の世界に入れるのかは、最初は説明しない。
- 「みらい博物館とは何なのか？」自体を大きな謎にする。
- 博物館の奥には、最初から見えるが開かない大きな扉がある構想。
- 発見と展示室を増やしていくことが、最終的に博物館・扉・案内ロボットの秘密につながる。
- ストーリーを読まなくてもゲームは遊べるようにする。

## 12. ビジュアル

### アート方針

**現代的なピクセルアート**を採用する。

- キャラクター・地形: ピクセルアート
- 背景: 情報量のあるピクセルアート
- 光・パーティクル: 現代的で滑らかな演出も許容
- UI・文字: 読みやすさ優先で高解像度表示
- 博物館の展示: ステージより情報量の多い大きな絵を使える

レトロゲームの技術的制約を再現することが目的ではない。

### 視点

- ゲームプレイは真横視点。
- 主人公は画面左下付近を基準位置とする。
- 世界は右から左へ流れる。
- 背景・前景を使って、巨大な恐竜、惑星、クジラなどを大きく見せる。

## 13. 画面

### 基準端末

**スマートフォン縦画面**を基準にする。

理由:

- URLを開いた状態から端末を回転させずに始められる
- 片手でタップして遊べる
- 上方向の空間を巨大な発見や背景演出に使える

### 画面上部

縦画面の上側は状況に応じて複数用途に使う。

- 通常時: 空・火山・木などの背景
- 発見時: 発見したものの名前や短い情報
- イベント時: 巨大な恐竜などの演出
- 上空: 翼竜など「上を見る」発見

UIは極力少なくし、世界を見る面積を広くする。

## 14. サウンド

初期版では **BGMと効果音のみ**。

- 音声読み上げは初期版には入れない。
- 将来的には、案内ロボットの音声や、鳴き声・楽器・言語など「音そのものを発見にする」ステージへ拡張できる。

## 15. Web版の技術方針

- **Nuxt**: 博物館、展示、ステージ選択、設定など
- **Phaser**: 自動スクロール、ジャンプ、物理、当たり判定、ステージ
- **TypeScript**: 共通のゲームロジックとコンテンツデータ

まずWebゲームとして作り、スマートフォンのブラウザでURLを開いてすぐ遊べることを優先する。

## 16. プレイ開始

初回もできるだけ早くゲームに入れる。

> URLを開く → タイトル → タップしてスタート → 恐竜ステージ

キャラクター選択や長い世界観説明をゲーム開始前に強制しない。

### 操作チュートリアル

独立したチュートリアル画面は作らない。

1. 自動で走り始める
2. 最初の小さな障害物が近づく
3. 指のアイコンが「トン」と表示される
4. プレイヤーがタップ
5. ジャンプに成功し、そのまま本編が続く

文字を読まなくても遊び方が分かることを目指す。

## 17. 最初に作る世界: 恐竜

最初のプロトタイプ／ステージのテーマは **ティラノサウルス**。

### ステージの流れ

1. 地層・岩・化石のある世界を走る
2. ティラノサウルスの化石を発見
3. 時間が巻き戻る演出
4. 地層や景色が変化して恐竜が生きていた時代へ
5. 生きている恐竜の世界を走る
6. ティラノサウルスの大規模な遭遇イベント
7. 逃げ切る
8. 時間が現在まで一気に進む
9. 生物 → 地層 → 化石 → 発掘 → 博物館展示、という流れを短い演出で見せる
10. 「今回の発見」を紹介
11. 博物館に展示が増える

### ティラノサウルス遭遇イベント

「倒すボス戦」ではなく、**遭遇すること自体がクライマックス**。

- 発見する
- 背景・森などから巨大なティラノサウルスが現れる
- 一時的に追いかけてくる
- 障害物をジャンプしながら逃げる
- 捕まる／ぶつかることに永続的なペナルティはなく、再挑戦できる
- 最後まで逃げ切ると時間経過の演出につながる

この「遭遇イベント」は、将来ほかの世界にも応用する。

例:

- 海: 巨大なクジラ
- 宇宙: ブラックホール
- 気象: 巨大な雷雲
