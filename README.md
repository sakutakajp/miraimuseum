# みらい博物館 / MIRAI MUSEUM

さまざまな「展示テーマ」と「ゲームジャンル」を組み合わせ、短いゲームを次々に遊べるWeb上の博物館。

恐竜、宇宙、深海、人体、数学、歴史、ロボットなどのテーマを、横スクロールアクション、シューティング、パズル、クイズなど異なる遊び方で体験する。ゲームごとに2D、2.5D、3D、ドット絵、イラストなど表現方法も変えてよい。

最優先するのは「教育ゲームにすること」ではなく、ゲームそのものを面白くすること。学問や知識はゲームの題材として扱い、遊んだ結果として興味が生まれることを狙う。

## 現在の実装と次のMVP

V2 MVPとして、共通のゲーム一覧・詳細・ステージ選択と、恐竜／宇宙のStage 1を実装済み。

- 今日のおすすめ（日付ごとに交互に選出）、テーマ／あそびかたによる絞り込み
- 恐竜ダッシュ: Phaserの2D横スクロール。約43秒、タップジャンプ、3ライフ
- MIRAI: STAR DIVE: Three.js + TresJSの3Dシューティング。80秒 / 144 BPM / 6場面、相対ドラッグ移動、自動射撃、3シールド、CHAIN / NEAR / RISK
- 小惑星ゲートから発光結晶の内部へ突入し、MIRAI BURSTで突破。クリア時に小惑星の発見と展示を解放
- 初回の操作デモ、一時停止、クリア／失敗、リトライ（STAR DIVEは導入を短縮）
- ステージ別BEST、ゲーム全体BEST、クリア、順次解放の端末保存（STAR DIVEはクリア時だけBESTを更新）
- 日本語／英語切替と日本語のルビ

Stage 2〜5は次の開発範囲。Stage 1クリア時にStage 2の解放状態を保存するが、未実装ステージの開始ボタンは表示しない。ゲーム全体BESTは現在、各ステージBESTの最大値として集計する。

### MVPを動かす

    npm ci
    npm run dev

Node.jsは22.19以上の22系、24.11以上の24系、または26以上を使う。開発サーバーはポート3000で起動する。

恐竜はタップ／クリック／Space／↑でジャンプ。宇宙は指のドラッグ、PCではマウスドラッグまたは矢印キー／WASDで移動。ⅡボタンまたはEscで一時停止でき、ページが非表示になると自動で一時停止する。

STAR DIVEの起動・描画・保存・検証の詳細は [実装メモ](docs/star-dive-implementation.md) を参照。

ゲーム登録は `app/games/catalog.ts`、共通結果は `StageResult`、保存処理は `app/games/progress.ts`。新しい作品は登録情報とゲーム固有の起動処理を追加して接続する。

記録は `mirai-museum:v2` に保存する。旧仕様の発見保存 `mirai-museum:v1` は保持し、V2のスコアには変換しない。言語設定は引き継ぐ。

### UI・アセットをStorybookで確認する

    npm run storybook

http://localhost:6006 を開く。Dev Containerでもポート6006を転送する。

- **UI**: 実際のゲームカード、クリア記録、ボタン、言語切替
- **Characters**: 主人公・ロボット・恐竜のドット絵、3D宇宙船と被弾状態
- **Objects**: ドット絵一覧、3Dの敵・隕石・アイテム、爆発・火花・被弾演出
- **STAR DIVE**: 実際の6場面、SHARD / CORE / GATE CORE、3段階の画質、reduced motion、HUD、クリア／失敗結果、小惑星展示
- **Backgrounds**: 恐竜の現在／太古の森／追跡場面、カード用イラスト、星雲・惑星を含む3Dの星空

上部の言語メニューで日本語／英語を切り替え、Controlsでスプライト、座標、背景の進行位置を変更できる。3D演出は `animate` でループ再生を切り替え、オフにすると `age` で任意の時点（0〜0.64秒）を静止確認できる。恐竜背景はPhaserの実シーンを一時停止して表示する。

ゲームカードと3Dアセットは本番ゲームとStorybookで同じVueコンポーネントを使用する。新しいストーリーは `stories/*.stories.ts` に追加する。

    npm run build-storybook
    npm run preview-storybook
    npm run test:storybook

静的出力は `storybook-static/`。ブラウザーテストで4カテゴリの描画と翻訳を検証する。

## 1. V2コンセプト

「みらい博物館」は単一ジャンルのゲームではなく、多数の小さなゲームを収録できる器とする。

ゲームの基本構造は次の3軸で考える。

**展示テーマ × ゲームジャンル × 表現方法**

例:

| 展示テーマ | ゲームジャンル | 表現 |
| --- | --- | --- |
| 恐竜 | 横スクロールアクション | 2D / ドット絵 |
| 恐竜 | シューティング | 2D / 3D |
| 宇宙 | シューティング | 3D |
| 深海 | 探索 | 2.5D / 3D |
| 数学 | パズル | 2D |
| 人体 | 探索 | 3D |
| 歴史 | アドベンチャー | イラスト |

同じ「テーマ × ジャンル」の組み合わせに複数作品を置いてよい。たとえば「恐竜 × シューティング」でも、やさしい作品、難しい作品、ボス戦中心の作品を別々に作れる。

難易度として変化させたいのは、主にゲームとしての難しさ。学習内容の難易度とは分離する。

## 2. プレイヤーと対象

- 子どもが直感的に遊べることを基準にする。
- デザインを幼児向けに固定せず、高難度ゲームやハイスコア挑戦は大人でも楽しめるようにする。
- 学習を必須にしない。ゲームとしての面白さを最優先する。
- 学問や知識は題材として使う。明示的な解説やクイズを全作品へ強制しない。

## 3. 博物館のナビゲーション

MVPでは博物館内をキャラクターで歩き回らない。ゲーム一覧・詳細画面を使ってすぐ遊べる構造にする。

将来は博物館内を歩き、展示に入る方式へ発展させられる。

### トップ画面

トップには「今日のおすすめ」を1作品、大きく表示する。

その下から2つの軸でゲームを探せる。

- **展示テーマから選ぶ**: 恐竜、宇宙、深海、人体、ロボットなど
- **あそびかたから選ぶ**: アクション、シューティング、パズル、クイズなど

「ゲームジャンル」という語を子ども向けUIでそのまま使う必要はない。「あそびかた」のような分かりやすい表現を優先する。

同じゲームへ、テーマ側からもジャンル側からも到達できる。

### ゲーム開始まで

1. トップまたは一覧からゲームを選ぶ
2. ゲーム詳細画面を開く
3. ステージを選ぶ
4. 数秒の操作デモを見る
5. プレイ開始

ゲーム詳細画面は共通レイアウトを使う。ただし背景、色、イラスト、3Dモデルなどは各ゲームの世界観に合わせて変える。

## 4. 共通するゲームデザイン

すべての作品を同じルールにするのではなく、「入りやすさ」と「短時間で遊べること」を共通化する。

### 画面と入力

- 基準端末はスマートフォン縦画面。
- タップ、長押し、スワイプ、ドラッグを使える。
- 原則としてタッチ操作中心で設計する。
- 仮想十字キーや多数の画面ボタンを前提にしない。
- PC対応は可能だが、ゲームデザインの基準はスマートフォン縦画面。

### 操作説明

各ゲームの初回プレイ時は、文章による長い説明を出さない。

指のアニメーションなどで、タップ、スワイプ、ドラッグといった必要な操作を数秒だけ見せ、すぐプレイへ移る。

### ステージ

- 1ステージは原則30秒〜1分程度。ただし作品の体験設計を優先し、必要なら約90秒まで使う。宇宙シューティングStage 1は約80秒。
- ステージ数はゲームごとに自由。
- Stage 1をクリアするとStage 2が開く、という順次解放を基本とする。
- 後半ほど難しくする。
- 数値だけを難しくするのではなく、新しい敵、ギミック、環境など「違う体験」を追加する。
- 失敗条件、ゲームオーバー、リトライ方式はゲームごとに設計する。

## 5. スコアと進行

原則として各ゲームにスコアを持たせる。ただし採点方法はゲーム内容に合わせる。

例:

- シューティング: 撃破数、命中、コンボ
- クイズ: 正解数、回答速度
- レース: タイム
- パズル: 手数、時間
- アクション: アイテム、到達、ノーミスなど

保存する記録:

- 各ステージのベストスコア
- ゲーム全体のベストスコア
- 解放済みステージ
- クリア進行状況

ゲーム一覧には進行状況と自己ベストを表示する。

MVPではログインを設けず、ブラウザーの端末保存を使う。将来、オンラインランキングへ拡張できるようにする。

現時点では、共通コイン、共通通貨、図鑑、発見コレクションなど、博物館全体をまたぐメタゲームは設けない。

## 6. 主人公

- 全ゲームで同じ主人公を使う。
- 主人公の具体的なキャラクターデザインは未決定。
- ゲームのテイストに合わせ、同じ主人公自身の表現も変える。

例:

- ドット絵ゲームではドット絵
- 3Dゲームでは3Dモデル
- 絵本風ゲームでは手描き・イラスト表現

「同じ主人公が、まったく異なる展示世界へ入る」ことを作品全体のつながりとして使う。

## 7. ビジュアル

### みらい博物館本体

博物館本体のUIは、**明るくカラフルで、少し未来感のあるデザイン**を共通スタイルとする。

### 各ゲーム

各ゲームの表現方法は自由。

- 2D
- ドット絵
- 2.5D
- 3D
- イラスト
- リアル寄り
- その他、そのゲームに適した表現

ゲーム部分まで博物館UIの見た目へ統一しない。作品ごとに世界観を大きく変えられること自体を「みらい博物館」の特徴にする。

## 8. 最初のゲームA: 恐竜 × 2D横スクロール

最初の作品の1つ。

### 基本ルール

- 2D横スクロールアクション。
- キャラクターは自動で右へ進む。
- タップでジャンプ。
- 全5ステージ構想。
- 各ステージ30秒〜1分程度を基本とする。
- Stage 1から順番に解放する。
- ステージごとに環境、登場する恐竜、ギミックを変える。
- 後半ほど難しくする。

### ライフとクリア

- ライフは3。
- 障害物や恐竜などに3回ぶつかるとステージ失敗。
- ゴールに到達すればステージクリア。
- クリア後に次ステージを解放する。

### スコア

次の要素を組み合わせてスコア化する。

- アイテム取得
- 障害物をうまく飛び越える
- 残りライフ
- クリアタイム

子どもはゴールを目指し、大人や慣れたプレイヤーはノーミスや高得点を狙える二層の遊びにする。

### 5ステージの方向性

各ステージで、背景だけを差し替えるのではなく、環境・恐竜・ギミックをまとめて変える。後半になるほど新しい体験と難しさを増やす。

具体的な5ステージの内容は今後決定する。

## 9. 最初のゲームB: 宇宙 × 3Dシューティング

恐竜ゲームと同時にV2の構造を検証するための2本目。

Stage 1は、単純な敵ウェーブ型シューティングではなく、映像・カメラ・音・入力・スコアを約80秒の振付として一体化する `MIRAI: STAR DIVE — ASTEROID BELT` として制作する。実装時は、この節の概要よりも **[STAR DIVE Stage 1 詳細実装仕様](docs/star-dive-stage1.md)** を優先する。

### 基本ルール

- 3Dシューティング。
- 宇宙船の後方から見る視点。
- スマートフォン縦画面。
- 指をドラッグすると宇宙船が上下左右に移動する。
- 射撃は自動。
- 全5ステージ構想。
- Stage 1は約80秒。144 BPM / 48小節を6つのsectionに分けて演出とゲーム進行を同期する。
- Stage 1から順番に解放する。
- 後半ほど新しい敵、障害物、ギミックを増やして難しくする。
- 障害物の近くをノーダメージで通過する `NEAR` と、その連続成功による `RISK` 倍率をStage 1の特徴にする。

### シールドと失敗

- シールドは3。
- 3回ダメージを受けるとステージ失敗。

### スコア

Stage 1ではターゲット破壊、`CHAIN`、`NEAR / RISK` を中心にする。残りシールドはクリアボーナスとし、レール進行のためクリアタイムは採点対象にしない。

3Dレンダリングは **Three.js + TresJS** を採用する。Nuxt/Vueとの統合にはTresJSを使い、Three.jsの3Dシーン、カメラ、レンダリング機能を利用する。MVPでは3D物理エンジンを追加せず、宇宙船・隕石・敵などの当たり判定はシンプルな距離判定やBounding Box判定で実装する。

## 10. 技術方針

現在の実装:

- Nuxt: サイト、博物館UI、画面遷移
- Phaser: 2Dゲーム（現在の恐竜ゲームを含む）
- Three.js + TresJS: 3Dゲーム（宇宙3Dシューティングから採用）
- TypeScript: アプリとゲームロジック
- localStorage: 現在の端末保存

V2では、Nuxtを「みらい博物館」の共通シェルとして維持し、ゲームごとに適したゲーム実装を載せられる構造へ変更する。

2Dゲームは現在のPhaser資産を活用する。3DゲームはThree.js + TresJSを使う。PhaserとThree.jsを1つのゲームエンジンとして混在させず、博物館側から共通のゲーム起動・終了・スコア・進行インターフェースを介して各ゲームを独立して扱う。

ゲーム固有のコードと、博物館側の共通情報を分離する。博物館側が最低限必要とするゲーム情報は次のようなものを想定する。

- game ID
- タイトル
- 展示テーマ
- ゲームジャンル / あそびかた
- ビジュアル
- ステージ一覧
- 進行状況
- ベストスコア
- ゲーム起動方法

これにより、新しいゲームを追加しても博物館本体を大きく書き換えない構造を目指す。

V2 MVPは「10ステージを完成させること」ではない。

以下が動けば最初の検証を完了とする。

- スマートフォン縦画面で博物館トップを表示できる。
- 「今日のおすすめ」が表示される。
- 「展示テーマから選ぶ」でゲームを探せる。
- 「あそびかたから選ぶ」で同じゲームを探せる。
- ゲーム詳細画面を開ける。
- ステージ選択画面を開ける。
- 恐竜Stage 1をプレイできる。
- 宇宙3DシューティングStage 1をプレイできる。
- それぞれ数秒の操作デモがある。
- クリア／失敗が成立する。
- スコアが計算される。
- ステージ別BESTとゲーム全体BESTが端末に保存される。
- 進行状況とBESTをゲーム一覧で確認できる。
- 2Dゲームと3Dゲームを行き来しても博物館本体が共通して動作する。

この検証後に、恐竜Stage 2〜5、宇宙Stage 2〜5を追加する。

## 14. 既存プロトタイプからV2への移行

既存の恐竜プロトタイプは捨てず、最初の「恐竜 × 2D横スクロール」作品へ活用する。

ただし、旧仕様の以下の点はV2では全体共通ルールではない。

- 全ゲームが横スクロール
- 操作がタップジャンプだけ
- ゲームオーバーなし
- 発見収集が全体の中心
- 発見率を主要な進捗にする
- ピクセルアートで全体を統一
- 1〜2分の長いステージ
- 博物館展示の収集でゲーム全体を進める

既存コードは段階的にV2へ移行する。まず博物館シェルとゲーム登録構造を作り、既存恐竜ゲームを1作品として接続し、その後に宇宙3Dシューティングを追加する。

---

この仕様の目的は、ひとつのゲームを完成させることではなく、**異なるテーマ・ジャンル・表現のゲームを継続的に追加できる「みらい博物館」という器を作ること**にある。
