# 暗号の遺跡 — Stage 1・2

実装日: 2026-10-11。提供された `caesar-game-codex-instructions.md` と3枚の参考画像を基準に実装。追加のユーザー指定に合わせ、アクセス時の導入画面・イラスト背景・漢字のルビを付け、クイズの文字と単語を日本語に変更した。

## 起動と経路

```sh
npm ci
npm run dev
```

ホームの「ゲーム一覧」→ `/games` →「暗号の遺跡」→ `/games/caesar`。アクセス時は導入画面で、橋と通信機を直す目的・2つのステージ・文字帯の動かし方をルビ付きで説明する。「冒険をはじめる」でStage 1へ進み、操作の案内へフォーカスを移す。再アクセス・再読み込みでも導入を表示し、保存した学習記録は保持する。開始後は「ステージ選択へ」からStage 1・2を選択できる。追加のAPI・ログイン・環境変数は不要。両ページは本番ビルドでprerenderする。

## 実装

| 責務 | ファイル |
| --- | --- |
| 46文字のひらがなの循環、文字列変換、1文字置換 | `app/games/caesar/cipher.ts` |
| 問題種別・入力・期待結果・通信記録 | `app/games/caesar/questions.ts` |
| 日本語の案内・ラベル・ヒント | `app/games/caesar/copy.ts` |
| 漢字の読み、ネイティブruby表示 | `app/games/caesar/readings.ts` / `ReadableText.vue` |
| 導入・開始・入力・実行・誤答・演出・次問待ちの状態遷移 | `app/games/caesar/state.ts` |
| 初回正誤・実行数・ヒント数、version 1の保存 | `app/games/caesar/progress.ts` |
| 導入画面・ひらがな表・UI・同期ドラッグ・復習欄 | `app/components/games/caesar/` |
| 背景のファンタジーイラスト＋橋・探検者・光の動き | `app/games/caesar/scene.ts` / `geometry.ts` |
| 共通のEngine・Scene・描画・visibility・解放 | 既存の `app/three-d/runtime.ts` |

暗号に使うのは「あいうえお…わをん」の46文字。「ん」の次は「あ」に戻る。濁点・半濁点・小さい文字を含まない単語を出題する。「ひらがなのならび」を開けば、両ステージで文字の順を確認できる。

Stage 1の文字帯は右に引くと左隣の文字が中央へ来る。3本の変位は共通で、表示と判定は指を離した整数のずらし量で更新する。長いドラッグは1回につき最大3文字。横ドラッグは `touch-action: pan-y` の領域内だけで扱い、縦スクロールを許可する。キーボードでは右キーが戻す、左キーが進める。ボタン操作も可能。すひす → しはし → さのさ → こねこを履歴にも残す。

Stage 2の通信記録は「あ → え」。解読は「すおは → こいぬ」、暗号化は「えほん → きむう」、1文字修正は「こねこ」を暗号化した「すひそ」を「すひす」に直す。実行するまで結果を伏せる。方向／数／修正位置／修正文字を変えると誤答結果を伏せる。解読は−3・+43、暗号化は+3・−43を認め、43の同値解には循環の説明を出す。修正位置を変えると未選択の場所を元の「すひそ」へ戻し、完成した「すひす」だけを正解にする。正解後は「次へ」を押すまで進まない。実行中の再実行や、演出中の二重遷移を受け付けない。リセット・ステージ選択・退出は保留タイマーを取り消す。

文字・ラベル・ボタンはDOM。背景はユーザーの追加指定に合わせた2枚の生成イラスト。参考画像の砂岩の遺跡、青緑の峡谷、金色の猫像・魔法の通信機を同じ画風で描いた。`public/caesar/` にWebPで収録し、文字は画像に焼き込まない。橋をつなぐ動き・探検者の横断・通信機の回復する光は、透明なBabylon.js 8のcanvasに小さなメッシュで重ねる。ふつう／かるいで描画解像度を切り替える。タブ非表示で描画を停止し、退出でScene・Engine・listener・ResizeObserverを解放する。背景失敗時も文字操作を続けられ、再表示では新しいcanvasを用意する。reduced motionでは演出を短縮。音声は追加していない。

ゲームと一覧の漢字にはルビを付ける。低学年向けに「出力」を「できた文字」にするなど案内を簡単にした。読みは `readings.ts` の最長一致で区切り、`ruby` / `rt` で表示する。読み上げではルビを重複しない。画質のselect選択肢はひらがな。

独立した保存キーは `mirai-museum:caesar:v1`。日本語化後も既存の記録を保持する。破損・非対応バージョン・保存拒否・容量不足でも遊べる。Stageのクリアは共通 `mirai-museum:v2` の `rosetta` にも保存し、既存ゲームの記録を保持する。単語やクリアを理解度の点数にはしない。終了時の復習欄では解読・暗号化・同じ鍵について、初回正誤・実行回数・ヒント数を表示する。

## 検証

```sh
npm run typecheck
npm test
npm run build
./node_modules/.bin/playwright test tests/browser/caesar.spec.ts
./node_modules/.bin/playwright test --config playwright.runtime.config.ts tests/runtime-browser/caesar.spec.ts
```

ロジックの単体検証は `tests/caesar.test.ts`。46文字の循環・逆変換・同値解・ひらがな以外の入力拒否も確認する。ルビの読み・文脈・漢字の網羅は `tests/caesar-readings.test.ts`。本番ブラウザ検証は `tests/browser/caesar.spec.ts`。資源とcontext lossの検証は `tests/runtime-browser/caesar.spec.ts`。本番ブラウザの全テストは `playwright test` で実行でき、既存ホーム・恐竜への遷移も確認する。導入・橋・通信機・終了・ゲーム一覧の実際のDOMでも、漢字にルビがあることを確認する。問題に英語の文字が残っていないこと、ひらがな表の展開と46文字の置換候補、キーボード・タッチでの開始、再入場・再読み込み後の記録保持を検証する。

確認対象はLinux ChromiumのPC 1440×1000、スマホ縦390×844・幅320、タッチのエミュレーション、キーボードのみ、reduced motion。実行前の結果非表示、誤答・ヒント・同値解・修正位置変更・再挑戦・保存拒否・描画不能を検証する。画面画像はPlaywrightの `test-results/production` に出力する。資源の測定結果は `test-results/runtime` に出力する。

2026-10-11の日本語化後の検証: 型チェック・本番ビルド成功、単体79件、暗号ゲームの本番ブラウザ7件、描画資源のブラウザ検証1件が通過。PC・スマホ縦の導入画面、PCの両ステージ・橋の接続・終了・一覧、スマホ縦の両ステージとひらがな表のスクリーンショットを作成した。

10回のやり直し前後で17メッシュ・6マテリアルを維持（Stage 1初期の描画5回）。3回のSPA退出ごとにEngine・Scene・描画ループ・listenerがすべて0、再入場で1・1・1・2に復帰した。タブ非表示でループ0、復帰で1。context loss後に資源0へ解放し、新しいcanvasで再表示できた。FPSはソフトウェアWebGLと自動操作の影響を受けるため、実機の性能値として扱わない。

iOS／Android実機、Safari、Firefox、Capacitor実機は未検証。背景はイラスト、動く部分は軽量な手続き的モデルで構成している。公開・本番デプロイは行っていない。
